# 09 — 多智能体协作

> 目标：掌握**多智能体（Multi-Agent）**架构——让多个各司其职的 Agent 协同完成复杂任务。
> 这是企业级智能体系统的进阶形态，也是拉开面试差距的加分项。

---

## 1. 为什么需要多个 Agent？

单一 Agent 面对复杂任务时力不从心：

| 问题 | 例子 |
|------|------|
| **上下文太长** | 一个 Agent 同时管"查资料+算数+写代码+翻译"，工具太多反而选错 |
| **角色冲突** | 既要"严谨"又要"创意"，一个 system prompt 难以兼顾 |
| **职责难隔离** | 不同领域的知识/工具混在一起，容易互相干扰 |

**多智能体的思路**：**像组建团队一样，让每个 Agent 专注一个角色**，由一个"管理者"调度。

```
单一 Agent：        一个全能选手，什么都干，容易顾此失彼

多 Agent：          ┌→ [研究员Agent]（只负责检索资料）
        [主管Agent] ─┼→ [写作Agent]（只负责写文案）
                    └→ [审核Agent]（只负责校对）
```

> 🔑 一句话：**单一 Agent 靠"一个聪明的大脑"，多 Agent 靠"分工协作的团队"**。

---

## 2. 多智能体架构的三种模式

| 模式 | 结构 | 特点 | 适用 |
|------|------|------|------|
| **Supervisor（主管）** | 一个主管调度多个子 Agent | 集中控制，清晰 | **最常用，本课重点** |
| **层级（Hierarchical）** | 主管下还有主管，树状 | 适合超大系统 | 复杂组织 |
| **网络/对等（Peer）** | Agent 之间平等对话 | 灵活，难控制 | 协商、辩论场景 |

---

## 3. Supervisor 模式：主管调度团队

结构：一个 **supervisor（主管）** 负责决定"下一步交给谁"，多个 **worker（工人）** 各自完成任务。

```
                          ┌────────────────┐
                          │  Supervisor     │ ← 主管：判断任务该给谁，何时结束
                          └───┬────┬───┬────┘
                    ┌─────────┘    │   └─────────┐
                    ▼              ▼             ▼
              [研究员Agent]   [写作Agent]    [审核Agent]
              检索资料        生成内容        校对润色
```

**每个 worker 本质上就是一个 `create_react_agent`**（第 07 篇），supervisor 是另一个负责"路由"的模型。

---

## 4. 手把手：用 LangGraph 搭一个 Supervisor 多智能体

### 4.1 先定义三个"工人" Agent

```python
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 工具：模拟"搜索资料"
@tool
def search(query: str) -> str:
    """搜索相关资料，返回内容摘要。"""
    return f"关于「{query}」的资料：这是一段相关资料内容……"

# 三个角色不同的 worker（用 state_modifier 定制人设）
researcher = create_react_agent(
    llm, tools=[search],
    state_modifier="你是研究员，只负责检索和整理资料，输出客观事实。"
)

writer = create_react_agent(
    llm, tools=[],
    state_modifier="你是写作者，根据给定资料写出流畅的文章。"
)

reviewer = create_react_agent(
    llm, tools=[],
    state_modifier="你是审核员，检查文章是否有错误，输出修改后的最终版。"
)
```

### 4.2 建主管节点和路由

```python
from typing import Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_core.messages import HumanMessage
from typing import TypedDict, Literal

# 状态：还是消息列表
class State(TypedDict):
    messages: Annotated[list, add_messages]

# 主管：一个带"路由能力"的模型，决定下一步给谁
members = ["研究员", "写作", "审核"]
options = members + ["FINISH"]

supervisor_prompt = (
    "你是项目主管，负责协调团队完成任务。\n"
    "团队分工：研究员(查资料)、写作(写文章)、审核(校对)。\n"
    "请判断下一步该交给谁，或任务完成时回答 FINISH。"
)

def supervisor(state: State):
    # 让主管模型从 options 里选一个（用结构化输出）
    supervisor_llm = llm.with_structured_output(
        type("Route", (), {"next": str})   # 简化：让它输出 {"next": "..."}
    )
    # 简化实现：主管直接基于当前消息返回下一步（实际应拼完整 prompt）
    from langchain_core.messages import SystemMessage
    resp = supervisor_llm.invoke(
        [SystemMessage(content=supervisor_prompt)] + state["messages"]
    )
    return {"messages": [HumanMessage(content=f"[主管决定] 下一步：{resp.next}", name="supervisor")]}

# 路由函数：读主管的决定，映射到具体节点
def route_supervisor(state: State):
    last = state["messages"][-1].content
    for m in members:
        if m in last:
            return m
    return "FINISH"
```

> ⚠️ 上面的 supervisor 实现做了**简化**（为了聚焦结构）。真实项目里会用更规范的
> `create_react_agent` + 结构化输出做主管，或直接用 LangGraph 官方提供的 `langgraph-supervisor` 库。

### 4.3 组装成一张大图

```python
# 三个 worker 作为子节点嵌入
graph = StateGraph(State)
graph.add_node("主管", supervisor)
graph.add_node("研究员", researcher)
graph.add_node("写作", writer)
graph.add_node("审核", reviewer)

graph.add_edge(START, "主管")
for m in members:
    graph.add_edge(m, "主管")   # 每个 worker 干完回到主管，继续调度
graph.add_conditional_edges("主管", route_supervisor, {**{m: m for m in members}, "FINISH": END})

app = graph.compile()

result = app.invoke({"messages": [HumanMessage(content="写一篇关于人工智能的科普文章")]})
print(result["messages"][-1].content)
```

```
                     ┌─────────────────────────────┐
                     │           主管               │
                     └──┬───────┬──────────┬───────┘
                ┌───────┘       │          └───────┐
                ▼               ▼                  ▼
            [研究员]         [写作]             [审核]
                │               │                  │
                └───────────────┴──────────────────┘
                         （完成后回到主管）
                         主管判断 FINISH → END
```

> 🎯 **关键结构**：所有 worker 完成后都**回到主管**，主管决定"下一个是谁"或"结束"。
> 这就是 Supervisor 模式的骨架。

## 5. 官方更简洁的方式：langgraph-supervisor

上面的手写版是为了让你理解原理。实际开发可用官方库，一行创建 supervisor：

```bash
pip install langgraph-supervisor
```

```python
from langgraph_supervisor import create_supervisor

workflow = create_supervisor(
    agents=[researcher, writer, reviewer],   # 三个 worker agent
    model=llm,                               # 主管用的模型
    prompt="你是主管，协调研究员/写作/审核完成任务。",
)

result = workflow.invoke({"messages": [("user", "写一篇科普文章")]})
```

> 面试加分：*"手写能理解原理，生产用 `langgraph-supervisor` 或基于 StateGraph 自定义，取决于对控制流的定制需求。"*

## 6. 多智能体的关键设计问题（面试重点）

### 6.1 怎么决定"下一个该谁"？（路由策略）

- **LLM 路由**：主管模型判断（最灵活，本课做法）
- **规则路由**：写死 `if` 逻辑（更可控，如"先研究员→再写作→再审核"）
- **函数路由**：根据结构化字段（如"状态机"）决定

### 6.2 怎么共享信息？

- **共享状态**：所有 Agent 读写同一份 `messages` 状态（LangGraph 默认）
- **共享内存/数据库**：写入统一存储
- **通过主管转发**：主管决定谁看什么

### 6.3 怎么防止失控？

- 限制最大步数（`recursion_limit`）
- 主管必须有"FINISH"出口
- worker 出错要能回到主管而不是崩溃

## 7. 常见坑

| 坑 | 现象 | 解决 |
|----|------|------|
| 主管不喊停 | 无限调度 | 明确 FINISH 出口 + `recursion_limit` |
| worker 返回后没回到主管 | 流程中断 | 每个 worker 都 `add_edge(m, "主管")` |
| 人设没区分 | 三个 Agent 干一样的活 | 用 `state_modifier` 明确各自身份 |
| 消息越积越多 | token 爆炸 | 裁剪/总结传递的消息 |

## 8. 面试高频题

**Q1：为什么要用多智能体？什么时候该用？**
> A：单一 Agent 面对复杂任务会上下文过载、角色冲突、职责混乱。当任务可拆解为多个专业子任务、
> 需要不同人设/不同工具时，用多智能体分工协作。典型场景：内容生产流水线、复杂客服、研发协作。

**Q2：Supervisor 模式的结构是怎样的？**
> A：一个主管（supervisor）模型负责调度，多个 worker agent 各司其职。每个 worker 完成任务后回到主管，
> 主管决定下一个 worker 或结束。用 LangGraph 实现时，主管是路由节点，worker 是子 agent 节点，
> 边全部回到主管。

**Q3：多智能体之间如何共享信息？**
> A：主要通过共享状态（LangGraph 中所有 agent 读写同一份 messages 状态）、共享存储（数据库/内存），
> 或由主管转发。共享状态是最简单直接的方式。

**Q4：`langgraph-supervisor` 和手写 StateGraph 实现多智能体，怎么选？**
> A：`langgraph-supervisor` 开箱即用、代码少，适合标准 Supervisor 场景；手写 StateGraph 能完全掌控
> 控制流（自定义路由、条件分支、持久化、人机协作），适合高度定制需求。理解原理后按需选择。
