# 11 — 开发流程与工作方法

> 目标：把前面 10 篇的技术能力，沉淀为**一套可复用的开发方法论**。
> 你学的不只是"怎么写代码"，更是"拿到一个需求，怎么把它变成可运行的智能体"。
> 末尾附**面试高频题汇总 + 答题思路**。

---

## 1. 智能体开发的思维框架

### 1.1 核心公式

```
智能体 = 大脑(LLM) + 手脚(工具) + 记忆(状态) + 规则(提示词) + 编排(图/链)
```

| 角色 | 组件 | 职责 |
|------|------|------|
| 大脑 | LLM（ChatOpenAI 等） | 理解、推理、决策 |
| 手脚 | Tools（@tool） | 执行真实操作（查库/调接口/算数） |
| 记忆 | 消息历史 / 状态 / checkpointer | 记住上下文 |
| 规则 | Prompt / state_modifier | 定义人设、行为规范、边界 |
| 编排 | LCEL / LangGraph | 组织"先做什么后做什么、什么条件做什么" |

### 1.2 拿到需求，先问 4 个问题

| 问题 | 示例答案 |
|------|---------|
| **① 智能体要"知道"什么？** | 公司制度（→ RAG）|
| **② 智能体要"会做"什么？** | 查订单、算账（→ Tools）|
| **③ 智能体要"记住"什么？** | 用户订单号（→ Memory）|
| **④ 流程是"固定"还是"动态"？** | 固定→Chain；动态多步→Agent |

## 2. 标准开发步骤（五步法）

### 第 1 步：判断用 Chain 还是 Agent

```
流程确定、步骤固定 → Chain（简单、可控、便宜）
任务开放、需多步决策 → Agent（灵活，但成本和风险更高）
```

**经验法则**：能确定流程就用 Chain，只有真正需要"自主决策"才上 Agent。
（面试很加分：*"不要为炫技而用 Agent，简单场景 Chain 更可靠"*）

### 第 2 步：设计工具（先有"手脚"再谈"大脑"）

把需求里的"动作"拆成工具，每个工具问三句：

1. 它叫什么？（`name`）
2. 何时用？（`description`）
3. 要什么参数？（`args_schema`）

```
需求："能查订单、能查库存、能算满减"
        ↓ 拆成三个工具
query_order(order_id) / check_stock(product) / calc_discount(amount, threshold, discount)
```

### 第 3 步：写提示词（定"人设 + 规则 + 边界"）

好的 system prompt 包含三要素：

```
① 身份：你是谁（"你是XX电商客服小悦"）
② 能力：你会什么、用哪些工具（"查订单用 query_order"）
③ 边界：什么能做、什么不能做（"不确定就说不确定，不瞎编"）
```

### 第 4 步：组装（选编排方式）

```python
# 简单 → create_react_agent 一行搞定
agent = create_react_agent(llm, tools=[...], state_modifier=prompt)

# 复杂 → StateGraph 显式建模
graph = StateGraph(State)   # 定义状态
graph.add_node(...)          # 加节点
graph.add_conditional_edges(...)  # 加分支/循环
app = graph.compile()
```

### 第 5 步：测试与调优（重点测"边界情况"）

| 测试类型 | 测什么 |
|---------|--------|
| 正常流程 | 标准问题能否正确完成 |
| 工具误用 | 模型是否会调错工具 |
| 记忆 | 多轮对话是否连贯 |
| 边界 | 资料外的问题会不会瞎编 |
| 稳定性 | 同样问题多次运行结果是否一致 |

> 调优三板斧：**temperature=0**（稳定）、**优化工具 docstring**（少调错）、**强化 prompt 边界**（少幻觉）。

## 3. 技术选型决策表（面试常问"怎么选"）

| 问题 | 选择 | 理由 |
|------|------|------|
| Chain 还是 Agent？ | 固定流程用 Chain | 简单可控便宜 |
| 结构输出怎么拿？ | `with_structured_output` | 底层 function calling 更稳 |
| 记忆怎么存？ | 生产用数据库/Redis，学习用内存 | 持久化、多用户隔离 |
| 知识问答怎么做？ | RAG（检索+生成） | 不微调模型也能答私有知识 |
| 复杂流程怎么编排？ | LangGraph | 分支/循环/持久化/人机协作 |
| 多智能体怎么搭？ | Supervisor 模式 | 集中调度，最常用 |

---

## 4. 常见坑汇总（避坑清单）

| 坑 | 现象 | 预防 |
|----|------|------|
| temperature 乱设 | 结构输出/工具调用不稳定 | 这类场景一律 0 |
| 工具 docstring 含糊 | 模型乱调/不调工具 | 写清"何时用+参数含义" |
| 无记忆/无隔离 | 多用户串话 | 用 session_id / thread_id 隔离 |
| 无限循环 | Agent 反复调工具 | `recursion_limit` + 优化描述 |
| 资料外瞎编 | RAG 失效 | prompt 强调"不知道就说不知道" |
| 密钥硬编码 | 泄漏风险 | `.env` + `.gitignore` |

## 5. 面试高频题汇总（附答题要点）

### 5.1 概念类

**Q：什么是 LangChain？为什么用它？**
> 统一接口（可替换模型/组件）+ 可组合（LCEL 拼装）+ 现成组件（链/工具/记忆/检索）。
> 核心价值是"标准化"和"复用"，本质是智能体工程方法论。

**Q：`langchain-core` 和 `langchain` 什么关系？**
> core 是基础抽象层（消息/Runnable/工具），langchain 是高层组件（链/智能体/记忆），
> 其他如 openai/community 是接入层。分层为了核心稳定 + 集成灵活。

**Q：Message 有哪些类型？**
> `SystemMessage`（人设规则）、`HumanMessage`（用户）、`AIMessage`（模型）、
> `ToolMessage`（工具回执）。

### 5.2 技术类

**Q：LCEL 是什么？`|` 管道怎么理解？**
> LangChain 表达式语言，把每个环节抽象成 Runnable，用 `|` 串联，统一 invoke/stream/batch 接口。

**Q：RAG 的完整流程？**
> 离线：文档→切分→向量化→向量库；在线：问题→检索→拼 prompt→生成。

**Q：什么是 Tool Calling？模型会执行函数吗？**
> 模型输出结构化 tool_calls 请求（含工具名+参数），由程序执行，结果以 ToolMessage 回传。

**Q：Agent 和 Chain 的区别？**
> Chain 路径固定，Agent 路径由模型动态决定，带"思考→行动→观察"循环。

**Q：LangGraph 三个核心概念？**
> State（状态）、Node（节点）、Edge（边，含条件边）。

**Q：多智能体 Supervisor 模式？**
> 主管调度多个 worker，worker 完成后回到主管，主管决定下一个或结束。

### 5.3 场景类（考察工程判断力）

**Q：怎么让 LLM 稳定输出 JSON？**
> `with_structured_output`（function calling）或 `PydanticOutputParser`，配合 temperature=0。

**Q：多用户场景怎么隔离记忆？**
> 用 `session_id`/`thread_id` 区分，各自独立的历史存储，生产用数据库/Redis。

**Q：Agent 死循环了怎么办？**
> `recursion_limit` 限步数 + 优化工具描述 + temperature=0 + 明确终止条件。

**Q：RAG 检索不准怎么优化？**
> 调分块策略（size/overlap）、换 embedding、混合检索、加 rerank、multi-query 改写。

### 5.4 开放类（拉开差距）

**Q：Agent 和 RAG 什么关系？**
> 正交的两个能力：RAG 解决"知识"（让模型知道私有数据），Agent 解决"行动"（让模型能调工具）。
> 可以结合：Agent 里挂一个检索工具，就变成了"会查资料的 Agent"。

**Q：LLM 的"记忆"是什么？**
> 不是真记忆，而是把历史消息塞回 prompt。短期靠消息裁剪，长期靠摘要/外置存储。

**Q：什么时候不用 Agent？**
> 流程固定、单步、可预测时用 Chain；不确定才用 Agent，避免过度设计。
