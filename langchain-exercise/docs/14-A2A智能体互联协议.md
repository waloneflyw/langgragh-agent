# 14 — A2A 智能体互联协议（Agent-to-Agent）

> 目标：搞懂 **A2A（Agent-to-Agent）协议**——它是什么、解决什么问题、怎么用代码写一个「能被别的智能体发现和调用的智能体」，
> 以及它和 [12 篇 MCP](12-MCP模型上下文协议.md) 的本质区别。
> 学完你就具备了「跨框架多智能体协作」的协议能力，这是 2026 年智能体架构的热点。

---

## 1. 一句话理解 A2A：让「智能体」和「智能体」对话

还记得第 12 篇的比喻吗？MCP 是 AI 的「USB-C 接口」。那 A2A 就是 AI 智能体之间的「**通用电话线**」。

| 协议 | 谁跟谁对话 | 解决什么 |
|------|-----------|---------|
| **MCP** | 智能体 ↔ **工具** | 智能体怎么接外部工具/数据 |
| **A2A** | 智能体 ↔ **智能体** | 智能体之间怎么发现、派活、协作 |

A2A 是 **Google 于 2025 年开源**、现已捐给 Linux 基金会开放治理的协议，和 MCP 互补：

```
┌─────────────┐   MCP    ┌─────────────┐   A2A    ┌─────────────┐
│   智能体 A   │ ───────▶ │  工具/数据库  │          │   智能体 B   │
└─────────────┘          └─────────────┘          └─────────────┘
        \                                              ▲
         \__________________ A2A ____________________/
               （智能体 A 把活儿派给智能体 B，并收回结果）
```

---

## 2. 为什么需要 A2A：多智能体的「巴别塔」问题

不同厂商/框架造出的智能体（LangGraph、CrewAI、AutoGen、各云厂商 Agent）**天生说不同的「语言」**，
互相之间无法直接对话。A2A 的价值和 MCP 一样：**把 N×M 变成 N+M**——

- 没有 A2A：每两个框架的智能体协作，都要写一套专用对接代码；
- 有了 A2A：每个智能体只需实现一次协议，就能被任何实现 A2A 的智能体发现和调用。

一句话：**MCP 让智能体「会用工具」，A2A 让智能体「会请别的智能体帮忙」。**

---

## 3. 核心概念（4 个必须懂）

| 概念 | 是什么 | 类比 |
|------|--------|------|
| **Agent Card** | 描述「我是谁、会什么、怎么联系我」的 JSON 名片，挂在 `/.well-known/agent-card.json` | 简历 + API 文档 |
| **Task** | 一个工作单元，有完整生命周期 | 一张工单 |
| **Message + Part** | 一条消息，由类型化「片段」组成（文本/文件/JSON） | 聊天消息 |
| **Artifact** | 智能体产出的成果（文档/图片/结构化数据） | 交付物 |

### Task 的生命周期（重点，面试常考）

```
submitted ──▶ working ──▶ completed
                │  ▲          ▲
                ▼  │          │
          input-required     failed / canceled / rejected
```

- `input-required` 状态尤其重要：任务干到一半，**智能体可以暂停、向对方要更多输入**——这和 [13 篇](13-LangGraph人机协作审批与反馈.md) 讲的人机协作是同一套思想，只是对象从「人」变成了「另一个智能体」。
- `pushNotifications` 能力允许智能体**主动推送**进度给对方（webhook），不必一直轮询。

---

## 4. 协议基础：JSON-RPC 2.0 之上

A2A 底层也是 **JSON-RPC 2.0**（和 MCP 同款思路），传输用 **HTTP + SSE 流式**，另支持 **gRPC**。
客户端靠 Agent Card 自动发现，靠 JSON-RPC 方法派任务、收结果。

> ⚠️ **版本坑（2026）**：A2A 早期（0.x）用 REST 风格方法名 `message/send`；**1.0 起改成了 JSON-RPC 风格
> `SendMessage`、`SendStreamMessage`**，且请求必须带 `A2A-Version: 1.0` 头，否则会被按旧格式解析而报错。
> 这个和 MCP 的 v1/v2 改名是同类坑，务必记住。

## 5. 上手：写一个 A2A Server

装包：

```bash
pip install "a2a-sdk[http-server]"   # 核心 SDK + FastAPI/Starlette 支持
```

一个**完整可运行**的 A2A 服务器（翻译智能体），存成 `a2a_server.py`：

```python
# a2a_server.py —— 一个能被别的智能体调用的「翻译智能体」
from a2a.types import (
    AgentCard, AgentSkill, AgentCapabilities,
    Message, TextPart, TaskState, TaskStatus,
)
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.apps.starlette import A2AStarletteApplication
from a2a.server.request_handler import DefaultRequestHandler
from a2a.server.tasks import InMemoryTaskStore
import uvicorn

# ① 名片：告诉别人「我是谁、会什么」
agent_card = AgentCard(
    name="翻译智能体",
    description="把任意中文翻译成英文",
    url="http://127.0.0.1:9999",
    version="1.0.0",
    capabilities=AgentCapabilities(streaming=True),
    skills=[
        AgentSkill(
            id="translate",
            name="中译英",
            description="把中文翻译成英文",
            tags=["translate", "language"],
            examples=["把'你好'翻译成英文"],
        )
    ],
    defaultInputModes=["text/plain"],
    defaultOutputModes=["text/plain"],
)


# ② 干活逻辑：继承 AgentExecutor，实现 execute
class 翻译Executor(AgentExecutor):
    async def execute(self, context: RequestContext, event_queue: EventQueue):
        # 取出对方发来的文本
        query = context.get_user_message().parts[0].text

        # 先报告「正在干」
        await event_queue.enqueue_event(
            TaskStatus(state=TaskState.working,
                       message=Message(role="agent", parts=[TextPart(text="翻译中……")]))
        )

        # 这里接真实翻译模型；教学用先伪造
        result = f"Translation: {query}"
        await event_queue.enqueue_event(
            TaskStatus(state=TaskState.completed,
                       message=Message(role="agent", parts=[TextPart(text=result)]))
        )


# ③ 组装：把名片 + 干活逻辑包成一个 ASGI 应用
request_handler = DefaultRequestHandler(
    agent_executor=翻译Executor(),
    task_store=InMemoryTaskStore(),   # 生产换成数据库实现
)
server = A2AStarletteApplication(agent_card=agent_card, http_handler=request_handler)

if __name__ == "__main__":
    uvicorn.run(server.build(), host="127.0.0.1", port=9999)
```

启动后，浏览器/curl 访问 `http://127.0.0.1:9999/.well-known/agent-card.json` 就能看到这张「名片」。

> ⚠️ 说明：A2A SDK 还比较新，不同小版本导入路径可能微调（如 `request_handler` vs `request_handlers`），
> 以 `pip show a2a-sdk` 的实际版本为准。上面是 1.x 的常见写法。

## 6. 调用这个 Server（客户端视角）

**方式一：curl 直接发 JSON-RPC（最直接，能看清协议原貌）：**

```bash
# ① 先看名片（发现）
curl -s http://127.0.0.1:9999/.well-known/agent-card.json

# ② 派活（注意方法名是 SendMessage，且带 A2A-Version 头）
curl -s -X POST http://127.0.0.1:9999/ \
  -H "Content-Type: application/json" \
  -H "A2A-Version: 1.0" \
  -d '{"jsonrpc":"2.0","id":1,"method":"SendMessage","params":{
        "message":{"role":"ROLE_USER","parts":[{"text":"你好，世界"}],"messageId":"msg-1"}
      }}'
```

**方式二：Python 客户端（SDK 自带）：**

```python
# a2a_client.py
import asyncio
from a2a.client import A2AClient   # 客户端；也常用 ClientFactory 创建

async def main():
    client = A2AClient(agent_card_url="http://127.0.0.1:9999")  # 自动拉名片
    # 发消息、收结果（不同版本 API 略有差异，以 SDK 实际为准）
    # ...

asyncio.run(main())
```

> 🔑 关键认知：客户端**不是写死接口**，而是先拉 Agent Card「自动发现」对方的能力和端点，再派活。
> 这正是 A2A 和「两个系统硬编码对接」的本质区别。

## 7. A2A vs MCP（面试必考）

| | MCP | A2A |
|---|---|---|
| 全称 | Model Context Protocol | Agent-to-Agent |
| 谁跟谁 | 智能体 ↔ 工具/数据 | 智能体 ↔ 智能体 |
| 核心原语 | Tools / Resources / Prompts | Agent Card / Task / Message / Artifact |
| 协作方向 | 智能体「用」工具 | 智能体「请」智能体 |
| 典型场景 | 接文件系统、数据库、API | 跨框架多智能体分工 |
| 关系 | 互补，不是竞争 | 互补，不是竞争 |

> 一句话总结：**MCP 管「智能体怎么伸手拿工具」，A2A 管「智能体怎么找同事帮忙」。**
> 一个复杂系统里两者常同时出现：智能体用 MCP 接工具、用 A2A 找别的智能体协作。

## 8. 常见坑

| 坑 | 现象 | 解决 |
|----|------|------|
| 方法名写错 | 报版本协商/方法不存在错误 | 1.0 用 `SendMessage`（不是旧的 `message/send`） |
| 漏 `A2A-Version` 头 | 请求被按旧格式解析而失败 | 带上 `A2A-Version: 1.0` |
| 用 `InMemoryTaskStore` 上生产 | 重启任务全丢 | 换数据库版 TaskStore |
| 忘了 `streaming` 能力声明 | 客户端拿不到流式结果 | `AgentCapabilities(streaming=True)` |
| 把 A2A 当 MCP 用 | 想让它「接工具」却语义错位 | 接工具用 MCP，智能体间协作才用 A2A |

## 9. 面试高频题

**Q1：A2A 协议是什么？解决什么问题？**
> A：Google 开源、捐给 Linux 基金会的开放协议，标准化「智能体之间的通信」，让跨厂商/跨框架的智能体
> 能互相发现、派活、协作，把 N×M 对接变成 N+M。

**Q2：A2A 的核心概念有哪些？**
> A：Agent Card（描述能力的名片）、Task（有生命周期的工单）、Message/Part（类型化消息片段）、
> Artifact（交付物）。

**Q3：A2A 和 MCP 的区别？**
> A：MCP 是智能体↔工具，A2A 是智能体↔智能体；原语不同（Tools vs Task）；定位互补不竞争。

**Q4：A2A 的 Task 有哪些状态？`input-required` 是干嘛的？**
> A：submitted / working / input-required / completed / failed / canceled / rejected。
> `input-required` 表示任务干到一半暂停、向对方要更多输入——是把「人机协作」思想搬到「智能体间协作」。

**Q5：A2A 底层协议和传输？**
> A：JSON-RPC 2.0 之上，HTTP + SSE 流式（也支持 gRPC）；靠 Agent Card 自动发现。
